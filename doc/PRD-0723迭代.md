## 1. 背景与目标

### 1.1 背景

当前后台已具备登录注册、会员管理、产品上架等基础能力。为支撑运营与商家侧业务，需要在不引入完整服务端的前提下（本期仍允许本地 mock / localStorage），补齐运营素材、商家商品体系与管理员个人资料三类能力。

### 1.2 本期目标

完成本期三个大改动：

1. **Banner 图管理 + 本地上传**
2. **商家管理模块（商家存在性 + SKU）**
3. **当前登录用户 Profile 修改**

### 1.3 非目标（本期不做）

- 真实后端 API / 数据库落库
- 对象存储（OSS/S3）云端上传
- 前台 C 端商城展示页完整实现（仅后台管理）
- 复杂权限体系（多角色审批流）

## 3. 改动点一：Banner 图管理与本地上传

### 3.1 需求说明

后台增加 Banner 管理模块，运营可维护首页/活动位 Banner 列表，并支持**从本地选择图片上传**（浏览器本地读取，本期可存 Base64 或 ObjectURL + localStorage 元数据）。

### 3.2 功能清单

| 编号 | 功能 | 说明 |
|------|------|------|
| 3.2.1 | Banner 列表 | 展示标题、预览图、排序、启用状态、更新时间 |
| 3.2.2 | 新建 Banner | 填写标题、跳转链接（可选）、排序、启用开关 |
| 3.2.3 | 本地上传图片 | 选择本地图片文件；校验类型与大小后预览 |
| 3.2.4 | 编辑 Banner | 修改文案、链接、排序、图片、启用状态 |
| 3.2.5 | 删除 Banner | 二次确认后删除 |
| 3.2.6 | 启用/停用 | 快速切换是否展示 |

### 3.3 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 系统生成 | 唯一标识 |
| title | string | 是 | Banner 标题，≤ 40 字 |
| imageData | string | 是 | 本地上传后的图片数据（Base64 或本地缓存键） |
| linkUrl | string | 否 | 点击跳转地址 |
| sort | number | 是 | 排序值，越小越靠前，默认 0 |
| enabled | boolean | 是 | 是否启用，默认 true |
| updatedAt | number | 系统 | 更新时间戳 |

### 3.4 本地上传规则

- 支持格式：`image/png`、`image/jpeg`、`image/webp`
- 单文件大小：≤ 2MB（超出提示失败原因）
- 上传后立即本地预览
- 刷新页面后仍可从本地存储恢复列表与图片（若受存储配额限制，需提示「本地存储不足」）

### 3.5 验收标准

1. 能新建至少 1 条 Banner，并看到本地上传图片预览  
2. 能编辑、删除、启用/停用  
3. 非法文件类型或超大小时有明确错误提示  
4. 刷新后数据不丢失（在浏览器配额允许范围内）

## 4. 改动点二：商家管理模块（商家 + SKU）

### 4.1 需求说明

新增「商家管理」模块，用于管理商家主体是否存在/可用，并维护其下的 SKU 信息（库存单元）。

### 4.2 商家管理功能

| 编号 | 功能 | 说明 |
|------|------|------|
| 4.2.1 | 商家列表 | 名称、联系人、状态、SKU 数量、更新时间 |
| 4.2.2 | 新建商家 | 创建商家主体 |
| 4.2.3 | 编辑商家 | 修改基础信息与营业状态 |
| 4.2.4 | 停用/启用商家 | 停用后其 SKU 不可再「上架销售」（后台标记） |
| 4.2.5 | 删除商家 | 若仍有 SKU，需二次确认（建议级联删除或禁止删除） |

### 4.3 商家字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 系统 | 商家 ID |
| name | string | 是 | 商家名称 |
| contact | string | 否 | 联系人 |
| phone | string | 否 | 联系电话 |
| status | enum | 是 | `active` / `inactive` |
| remark | string | 否 | 备注 |
| updatedAt | number | 系统 | 更新时间 |

### 4.4 SKU 管理功能

在商家详情或商家行内进入「SKU 管理」：

| 编号 | 功能 | 说明 |
|------|------|------|
| 4.4.1 | SKU 列表 | 按商家过滤：名称、编码、价格、库存、状态 |
| 4.4.2 | 新建 SKU | 绑定当前商家 |
| 4.4.3 | 编辑 SKU | 修改价格、库存、名称等 |
| 4.4.4 | 上架/下架 SKU | 控制可售状态 |
| 4.4.5 | 删除 SKU | 二次确认 |

### 4.5 SKU 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 系统 | SKU ID |
| merchantId | string | 是 | 所属商家 |
| name | string | 是 | SKU 名称 |
| skuCode | string | 是 | SKU 编码，同商家内唯一 |
| price | number | 是 | 售价，≥ 0 |
| stock | number | 是 | 库存，≥ 0 整数 |
| status | enum | 是 | `on` / `off` |
| updatedAt | number | 系统 | 更新时间 |

### 4.6 业务规则

1. 商家 `inactive` 时，其下 SKU 不可新建为上架；已上架 SKU 批量标记为不可售或提示运营先下架  
2. 同一商家下 `skuCode` 不可重复  
3. 删除商家时：若存在 SKU，弹窗说明将一并删除（或要求先清空 SKU）——本期采用**级联删除 + 二次确认**

### 4.7 验收标准

1. 可创建商家并看到列表  
2. 可为商家新增/编辑/上下架/删除 SKU  
3. 同商家重复 SKU 编码有校验提示  
4. 停用商家后，SKU 上架操作被拦截或自动下架（实现一种即可，需在界面说明）

## 5. 改动点三：当前登录用户 Profile 修改

### 5.1 需求说明

后台增加「个人资料 / Profile」能力，**当前登录管理员**可修改自己的展示信息与登录密码（本地账号体系）。

### 5.2 功能清单

| 编号 | 功能 | 说明 |
|------|------|------|
| 5.2.1 | 查看 Profile | 展示当前用户名、角色、展示名、邮箱/手机（可选） |
| 5.2.2 | 修改基础资料 | 修改昵称、邮箱、手机号等非登录名信息 |
| 5.2.3 | 修改密码 | 校验原密码后设置新密码 |
| 5.2.4 | 保存反馈 | 成功/失败有明确提示；保存后顶栏展示名同步更新 |

### 5.3 字段定义

| 字段 | 类型 | 可改 | 说明 |
|------|------|------|------|
| username | string | 否（本期） | 登录名，创建后不可改 |
| displayName | string | 是 | 昵称/展示名 |
| email | string | 是 | 邮箱，格式校验 |
| phone | string | 是 | 手机号，可选 |
| password | string | 是（经原密码） | 登录密码，≥ 6 位 |
| role | string | 否 | 角色展示 |

### 5.4 交互与校验

1. 修改密码必须填写：原密码、新密码、确认新密码  
2. 原密码错误 → 提示「原密码不正确」  
3. 两次新密码不一致 → 提示「两次输入不一致」  
4. 仅允许修改**当前登录账号**，不可改其他管理员资料（本期不做账号代管）

### 5.5 验收标准

1. 登录后可打开 Profile 页并看到当前账号信息  
2. 修改昵称后刷新仍保留，且布局顶栏同步  
3. 正确原密码可改密；错误原密码失败  
4. 未登录访问 Profile 会跳转登录页
